Separate Dynamic DeepHit models for RL states and rewards

We use Dynamic DeepHit for two purposes: its final-timestep latent representation is the RL state, and its hourly health score defines the reward, r_t = HS_{t+1} − HS_t. Both are computed from 72-hour input windows that include fluid and vasopressor doses, because treatment history shapes how physiology should be interpreted. The two uses place different requirements on how the most recent dose is handled, so we train a separate model for each.

In the RL dataset, the action at step t is the dose recorded at hour t+1, and the state at t is computed from the window ending at hour t. Every dose in that window, including hour t’s, has already been given and is part of the patient’s history rather than the decision being evaluated. The state model therefore sees all doses unmasked (actions_shift=True). This lets the agent distinguish starting from continuing a vasopressor, provides the current dose that the behaviour policy needs, and acts as a partial proxy for severity not captured in the recorded physiology.

The reward model must not see the action it is evaluating. HS_{t+1} is computed from the window ending at hour t+1, which contains the dose that constitutes a_t. If that dose were visible, the reward would change because the action appeared in the model’s inputs, independently of any physiological response. The model would penalise treatment directly, since it has learned that receiving vasopressors marks a sicker patient. The reward model is therefore trained and run with the dose columns of each window’s final hour masked (actions_shift=False).

Masking the final hour removes the immediate dependence of r_t on a_t, but not all of it. One hour later the dose is no longer in the final row, so it can still influence subsequent health scores, and through the telescoping reward this enters the return. As a sensitivity analysis, we therefore also train a reward model with treatment removed from its inputs entirely, so the reward depends on treatment only through recorded physiology. Each Dynamic DeepHit configuration is trained with five seeds. Because single-seed hourly rewards agree only weakly across seeds, the reward is computed from the seed-averaged health score, and every RL seed is trained on the same reward. RL seed i uses the latents of Dynamic DeepHit seed i as its state.
